## 1. 측정 결과 (PC 크롬 헤드리스, 390×844, 4.28 빌드)
| 항목 | 값 | 판단 |
|---|---|---|
| 결과 파일 크기 | 25.1MB → **24.5MB** | 단일 HTML 규칙 때문에 그림·소리가 base64로 들어 있음 |
| 시작(DOMContentLoaded) | 678ms → **483ms** | 큰 배경 그림을 처음 쓸 때만 풀도록 바꾼 효과 |

용량 구성: 캐릭터 그림(charpx) 8.1MB · 아이템/배경(itempx) 7.5MB(그중 배경류 6.6MB) · 소리 5.8MB · 물고기 1.2MB · 코드 0.7MB

## 2. 이번에 적용한 것 (4.28)
1. **큰 배경 그림 늦게 풀기**: 낚시터 배경·물속·시간대 지도·계절 덧그림·수족관 테마(약 60장)를 시작할 때 전부 디코딩하던 것 → 그 낚시터에 갈 때/처음 그릴 때만 (`src/04f_items.js` IPLAZY·ipOk·ipWarm). 휴대폰 메모리 사용이 크게 줄 것으로 [추정] (큰 그림 1장 ≈ 5MB 메모리).
2. 그림이 아직 안 풀렸을 때 시간대 덧칠(BFX)이 멈춰 버리지 않게 다음 프레임에 다시 시도 (`06m_bgfx.js` bfxTick·bfxOverlay).
3. 꾸미기 옛 도트 그림(outfitpx 0.6MB)을 빌드에 넣지 않음 — 카드는 게임 속 실제 의상 그림을 씀. 파일은 보관.

## 3. 남은 후보 (효과 큰 순서) — 다른 AI/개발자에게 이 부분을 그대로 주면 됩니다

```
[요청] 낚시왕 왕낚시(단일 HTML 웹 게임, 빌드: python build.py) 성능 최적화
규칙: 결과물은 dist/haneul-fishing.html 하나(base64 내장) 유지 · 세이브 키 haneul-fish-v4 계열 절대 변경 금지 ·
      그림 품질이 눈에 띄게 떨어지면 안 됨 · 바꾸기 전/후 화면 캡처 비교 · tests/ 전체 통과

1) 캐릭터 그림 8.1MB 줄이기 (assets/charpx.json, 30세트×19포즈=570장, webp q74 높이 240px)
   - 게임 화면에서 캐릭터는 높이 약 150~200px로 그려짐 → 높이 200px·q70으로 다시 만들면 약 30% 감소 예상
   - tools/import_charsheet.py의 frame() 크기 상수만 바꿔 다시 만들 수 있음(원본 시트는 assets/incoming/)
2) 계절 덧그림(bgs_*, 2.4MB)·시간대 지도(bgfx_*, 1MB) 해상도 낮추기
   - 덧그림은 원본 배경(1600px) 위에 섞이므로 1200px로 줄여도 티가 거의 안 남 → tools/make_bg_fx.py 출력 크기 조정
3) 소리 5.8MB: 효과음은 짧으니 그대로, 배경음악(BGM)만 비트레이트 96kbps→64kbps 모노로 (tools/make_audio.py)
4) 휴대폰 실기기 측정: 크롬 원격 디버깅으로 낚시 1분 동안 FPS·메모리 기록, 저사양 자동 전환(autoLow)이 너무 늦게/자주 켜지지 않는지
5) 한 프레임에 새로 만드는 그라디언트(createRadialGradient) 줄이기: 계절 빛 알갱이·수족관 오라·보물 방울 — 저사양(LOWGFX)일 때는 단색 원으로
```

## 4. 일부러 안 한 것
- 파일을 여러 개로 나누기: 프로젝트 규칙(단일 HTML) 위반이라 안 함. 안드로이드 앱으로 갈 때는 앱 안에 들어가므로 25MB도 문제 없음.
- 그림 품질 낮추기(위 1·2): 화면 비교가 필요해서 이번엔 요청문으로만 남김.
